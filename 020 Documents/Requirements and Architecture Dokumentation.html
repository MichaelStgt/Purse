BudgetFlow

.NET MAUI 10 Offline-First Budgeting Application

1. Project Vision

BudgetFlow is a modern offline-first personal finance and budgeting application built with .NET MAUI 10, CommunityToolkit MVVM, and CommunityToolkit DataSync.

The application is designed around a resilient synchronization architecture where all data is written locally first and synchronized with the server whenever internet connectivity becomes available.

The solution architecture is intentionally modular to allow future reuse of the MVVM layer, business logic, synchronization components, and APIs across multiple applications.

4. MVVMBaseTen Library Strategy

The reusable MVVM infrastructure will be centralized inside the existing MVVMBaseTen library.

This allows the same MVVM infrastructure to be reused across multiple .NET MAUI applications.

4.1 MVVMBaseTen Responsibilities

  • Base syncable model classes
  • Validation infrastructure
  • Navigation helpers
  • Busy state handling
  • Async command helpers
  • Service abstractions
  • Connectivity monitoring
  • Synchronization helpers

4.3 Validation Strategy

All ViewModels inherit from ObservableValidator.

Validation is implemented using:

  • DataAnnotations
  • ObservableProperty partial methods
  • Automatic validation triggering

public partial class TransactionEditorViewModel : BaseViewModel { [ObservableProperty] [NotifyDataErrorInfo] [Required] [Range(0.01, 999999)] private decimal amount;

partial void OnAmountChanged(decimal value)
{
    ValidateProperty(value, nameof(Amount));
}

}

7. Offline-First Synchronization

BudgetFlow uses an offline-first synchronization model.

Every change is written to SQLite immediately.

Synchronization with the server occurs later whenever connectivity becomes available. 


User Action ↓ Write to SQLite ↓ Update UI ↓ Queue Sync Operation ↓ Internet Available? ↓ Push to API

9. EF Core Migration Strategy

This section explains the recommended migration workflow for the local SQLite database.

9.1 Install Required Packages


Install-Package Microsoft.EntityFrameworkCore Install-Package Microsoft.EntityFrameworkCore.Sqlite Install-Package Microsoft.EntityFrameworkCore.Design Install-Package Microsoft.EntityFrameworkCore.Tools

9.2 Create the DbContext


public class BudgetFlowDbContext : DbContext { public DbSet Transactions => Set(); public DbSet Categories => Set();

public BudgetFlowDbContext(DbContextOptions<BudgetFlowDbContext> options)
    : base(options)
{
}

}

9.3 Configure the SQLite Database


string dbPath = Path.Combine(FileSystem.AppDataDirectory, "budgetflow.db");

builder.Services.AddDbContext(options => { options.UseSqlite($"Filename={dbPath}"); });

9.4 Create a Design-Time Factory

This is the part that is commonly missing and causes migration problems. 


public class BudgetFlowDbContextFactory : IDesignTimeDbContextFactory { public BudgetFlowDbContext CreateDbContext(string[] args) { var optionsBuilder = new DbContextOptionsBuilder();

optionsBuilder.UseSqlite("Filename=budgetflow.db");

    return new BudgetFlowDbContext(optionsBuilder.Options);
}

}

9.5 Create the Initial Migration


Add-Migration InitialCreate

Or using CLI:


dotnet ef migrations add InitialCreate

9.6 Apply the Migration


Update-Database

Or:


dotnet ef database update

9.7 Automatic Migration at App Startup


using var scope = serviceProvider.CreateScope();

var db = scope.ServiceProvider .GetRequiredService();

await db.Database.MigrateAsync();

9.8 Future Schema Changes

Example: 


[ObservableProperty] private string currencyCode = "EUR";

After changing models: 


Add-Migration AddCurrencyCode Update-Database

9.9 Recommended Migration Workflow

  1. Modify model classes
  2. Create migration
  3. Review generated migration code
  4. Apply migration locally
  5. Test app startup
  6. Commit migration files to Git

9.10 Important Recommendation

Keep migrations in a dedicated Infrastructure project rather than inside the MAUI project.

This avoids many design-time tooling issues.
